## A.5 完整命令

```bash
python3 - <<'PY'
import json, collections
L=open('/tmp/prod-now.jsonl').read().splitlines()
ALL=[json.loads(l) for l in L if l.strip()]          # 含首行 → 失败分母 17,053
F=[r for r in ALL if r.get('status')!='ok']
evs=lambda r:[e for e in (r.get('events') or []) if isinstance(e,dict)]
has=lambda r,t:any(e.get('type')==t for e in evs(r))
det=lambda r,t,k:any(e.get('type')==t and k in (e.get('detail') or '') for e in evs(r))
em=lambda r:r.get('err_msg') or ''
zn=lambda r:not (r.get('nodes') or [])
blk=lambda r:det(r,'quota_halt','blocked')
P5={'upstream http 500','upstream http 502','upstream http 503','upstream http 504','upstream http 520'}
def clsP(r):
    if blk(r): return 'P1 闸门拒绝'
    if has(r,'connect_error'): return 'P2 连不上'
    if det(r,'upstream_error','429'): return 'P3 上游429'
    if det(r,'upstream_error','403'): return 'P4 上游403'
    if em(r) in P5: return 'P5 上游5xx'
    return 'P6 其他'
def clsM(r):
    if blk(r): return 'M0 闸门拒绝'
    return 'M '+em(r) if em(r).startswith('upstream http ') else 'M 传输/流层'
print("成功",sum(1 for r in ALL if r.get('status')=='ok'),"失败",len(F))
for nm,fn in [('P',clsP),('M',clsM)]:
    c=collections.Counter(fn(r) for r in F)
    for k,v in sorted(c.items()): print(f"   {nm} {k:20s} {v:6d} {100*v/len(F):6.2f}%")
    print(f"   {nm} 合计 {sum(c.values())} / {len(F)}  OK={sum(c.values())==len(F)}")
print("connect_error事件",sum(1 for r in F if has(r,'connect_error')))
print("零节点",sum(1 for r in F if zn(r)),"无任何事件",sum(1 for r in F if not evs(r)))
print("429事件",sum(1 for r in F if det(r,'upstream_error','429')),"403事件",sum(1 for r in F if det(r,'upstream_error','403')))
print("err_msg=429",sum(1 for r in F if em(r)=='upstream http 429'))
print("闸门",sum(1 for r in F if blk(r)),"闸门∩429事件",sum(1 for r in F if blk(r) and det(r,'upstream_error','429')))
print("零节点失败∩429事件",sum(1 for r in F if zn(r) and det(r,'upstream_error','429')))
print("零节点失败 err_msg=429",sum(1 for r in F if zn(r) and em(r)=='upstream http 429'))
PY
```

## B.4 台账「方案 A 的预期上限约 +0.57pp」——**判定：可复现（单一假设下），但它是乐观上界**

**公式**：
```
+0.57pp = 3,284（闸门 blocked） × 35.49%（直连放行成功率 = 3,614 / 10,183） ÷ 204,237
        = 1,165.5 ÷ 204,237 = 0.5707pp  →  +0.57pp   ✅
```
（配额代码自己的说法可交叉印证：`quota_halt.go:13-14`「实测三天误拒 3,284 条…那批直连放行后成功率有 35.5%（约 1,166 条本可成功）」——1,166/204,237 = 0.571pp，同一算法。）

**但它对"放行成功率"这个假设极度敏感**：

| 假设的放行成功率 | 怎么来的 | 挽回条数 | 提升 |
|---|---|---|---|
| 35.49% | 零节点记录整体成功率 3,614/10,183（55 天平均） | 1,165.5 | **+0.57pp** |
| 52.38% | 只算「没被闸门挡」的零节点记录 3,614/6,899 | 1,720.3 | +0.84pp |
| 30.05% | 只算风暴三天（09-19/20/21）零节点 2,724/9,066 | 986.7 | +0.48pp |
| 7.91% | 09-19 单日零节点 249/3,149（当天直连几乎全被 429） | 259.7 | +0.13pp |

⇒ 合理的说法是：**「上限量级 +0.1pp ~ +0.6pp，取 +0.57pp 为乐观上界」**，并写明它假设「闸门挡下的请求若放行，成功率 = 同期零节点记录的整体成功率 35.49%」。注意这**不是严格上界**：闸门恰恰是在直连出口吃到 429 时才拉起（`quota_halt.go:5-16`），所以那批请求放行后更接近风暴期的 30.05% 或 09-19 的 7.91%，真实值应在 **+0.13 ~ +0.48pp** 一侧。台账写「上限约 +0.57pp」在方向上没错，但用「上限」二字会让人以为不会更高（52.38% 那行就是 +0.84pp），建议改成「乐观上界 ≈ +0.57pp，稳健区间 +0.13 ~ +0.48pp」。
