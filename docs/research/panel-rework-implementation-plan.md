## 3. 实现顺序（单文件 `static/admin.html`，一次改完）

1. **外壳与令牌**：`[data-theme]` 双主题、`currentTheme()` 单一来源、`reuseChart()`/`applyChartTheme()`、导航 6 项
2. **概览**（风险最低，先落地建立基线）
3. **节点**（新状态语义：215 → 可用/判死/冷却；三态冗余编码不只靠颜色）
4. **日志 + 分析**（一页两子视图 + 联动：点分析里的模型/时段 → 明细带上筛选）
5. **设置**（8 控件 + 只读诊断 + 危险区；出口/直连组**不得出现**）
6. **模型**（单开，保留未上线卡）

## 4. 验收点（一次性验收，逐页）

- **id 契约零丢失**：`u3-overview-landing-spec.md` 列的 11 条断言（`#tcTotalToken`/`#gIn`/`#gOut`/`#gCR`/`#ovHealthy` 等）全部保留
- **数据口径**：概览只显示有成功记录的模型；**全部请求（含未映射/失败）只能在日志+分析页查到**；表「输入」列统一为「不含缓存」
- **双主题 + 三视口**（1440/390/320）无横向溢出、无 `pageerror`、无外部请求
- **图表实例数**：概览 4→3 已声明；不得悄悄增加
- **删除项零残留**：出口组、被删/写死的 6 个设置项英文键名 0 命中
- **状态冗余编码**：节点三态不只靠颜色；未映射/失败/超时同理
- **门禁**：`docs/mockups/u3/verify.py` 全量（当前 206 态基线）扩展到最终页面集，全部 ALL_PASS
- **独立验收**：实现方与验收方分离；验收方自造断言、做变异（至少 3 个），不接受"测试被改宽"

## 5. 上线

- 一次合并 `test`→`main`、Actions 构建、`docker compose pull && up -d`
- 上线前打回滚标签
- 上线后只读自检：面板 gzip 体积与 `Vary`、6 页可达、接口 200、无 `pageerror`、概览数字与 `/api/stats` 一致

## 6. 风险

| 风险 | 缓解 |
|---|---|
| `admin.html` 2496 行单文件，多处 id 被脚本引用 | 先冻结 id 契约清单，落地后逐条比对 |
| 6 页一次改完，回归面大 | 分页提交（同分支内多次 commit），但**只做一次验收与一次上线** |
| 分析页依赖聚合端点，若端点未就绪 | 分析视图标「数据未就绪」占位，禁止用假数字凑版式（已有教训） |
| 与调用日志改造并行改同一分支 | 日志改造先合并上线，面板改造在其后进行 |
