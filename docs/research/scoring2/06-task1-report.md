### 1.1 blip：失败只压分母

旧逻辑 `EffS += w*(1 - weight*0.2)`，把一次满失败折成 0.8 个成功。新逻辑：

```go
if blip {
    st.EffN += w * scoringBlipFactor // 0.2
    st.BlipFails++
} else {
    st.EffN += w
    st.EffS += w * (1.0 - oc.weight)

```

- 满失败在 blip 内：`EffN += 0.2w`、`EffS += 0`。

### 1.2 探测恢复

```go
func probePenalty(lastProbeAt, lastProbeFailAt, now time.Time) float64 {
    if lastProbeFailAt.IsZero() || lastProbeAt.After(lastProbeFailAt) { return 1.0 }
    elapsed := now.Sub(lastProbeFailAt)
    v := 0.4 + 0.6*elapsed.Seconds()/scoringProbeFailRamp.Seconds()
    if v > 1 { v = 1 }
    return v
}
```

- `probe` 分项 = 原新鲜度分 × `probePenalty`。
- 65 分封顶条件增加 `now - LastProbeFailAt < 30min`。
- `observeProbe` 连续 2 次成功时 `ProbeFailTimes = nil`。
- 参数：`scoringProbeFailRamp = 2h`、`scoringProbeCapWindow = 30min`。

### 1.3 403 池级判定

- 订阅键 = 节点名 `::` 前缀（`scoringSubOf`，无前缀退回节点名）。
- 记录级先扫描本条记录内所有 `http 403` 的订阅，再叠加 `sub403` 中 10 分钟窗口内的订阅。
- 不同订阅数 ≥ `scoring403PoolSubs`(2) ⇒ 本条所有 403 不计质量（`Attempts` 也不加），`scoringStats.Pool403++`，`scoreNode` 输出 `pool_403` 原因。
- 单订阅：`Attempts++`、`Fail.Cred++`、`EffN += w`（blip 内 `0.2w`）、`EffS += 0`。
- `401/410/426` 仍走原 cred 逻辑；`403 FreeTierError` 仍走 quota（不参与本判定）。

## 6. 已知限制 / 未决风险

1. **全量测试有 2–3 个非本任务失败**（本地 `zz_*` 验证文件，未改）：
   - `TestIP4RVLiveServedDrift` / `TestIP4RVDocsDrift`（`zz_ip4agg_reverify_test.go:227/244/282`，两次全量均失败）
   - `TestFT_BothLoopsPatched`（`zz_freetier_confirm_test.go:426`，仅第一次全量失败，第二次通过，属 flaky）
   这些文件是仓库内历史验证脚本，失败与 `node_scoring.go` 无关；本任务提交不包含它们。其余包内测试全绿。
2. **旧参考对账弱化**：旧 `scores.json` 来自旧公式，只有 4 个节点可精确对账；Task-1 新规则的正确性由 6 个新测试 + 4 个变异 + T4 独立复算保证。T4 若仍用旧参考分，应预期大范围不一致。
3. **blip 权重近似**：对 10-20 之前的存量证据，用 `blip_fails × 平均衰减权重` 还原，可能高估旧 blip 的权重（旧证据衰减更小），个别节点 after 偏低约 1–2 分；日本02/香港01 的全部证据都在窗口内，数字精确。
4. **10-24 的 2183 条 403 仍归单订阅**：按 Task-1 计划，单订阅 403 计节点 cred；只有多订阅同窗才判形态级。若事后确认 10-24 是形态级（单订阅也可能代表上游整体），则这批 403 应整体豁免，而不是靠 blip 把分母压到 0.2。T4 需要结合订阅/ASN 数据复核。
5. **5 个 0 成功节点仍 ≥50**：`0.6q + 0.2reach + 0.2latency` 在 q≈0 时下限仍约 40，探测健康时可到 58.7。Task-1 计划未要求零质量封顶；选择器/后续任务若把「0 成功」当硬门槛，应直接用 `quality` 或 `last_ok_age_s`，不要只看总分。
6. **before/after 时间差 55 分钟**：不是同一时刻的 A/B；恢复节点的解锁时间落在两者之间。严格同刻对比需 T4 用同一份状态重放。
