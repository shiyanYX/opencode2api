# 数据看板结构与视觉范式参考

> 目的：为 `static/admin.html` 的前端重构提供「可行方向」判断，不是选一个项目照抄。
> 范围：只读调研。未改代码、未 commit、未碰 docker、未重启服务。
> 核验时间：2026-10-26。所有 URL 均实际请求过；商业产品后台需登录的部分，只以官方文档/公开演示为依据，不声称看过登录后界面。
> 4 页口径：与 `docs/research/ui-preview-brief.md` 对齐——总览 / 请求日志 / 节点池 / 设置。设置页承接原「代理与模型」的配置项；订阅/配额是否保留，按最终数据源决定。若最终口径不同，按「摘要页 / 流页 / 清单页 / 配置页」四类映射即可。

**一句话结论**：最稳的结构是「左侧固定侧栏 + 单列高密度」（方向 A）；「顶部横向 + 单列报告」（方向 B）适合做排版层；「窄图标轨 + 面板画布 + 抽屉」（方向 C）只借下钻，不借面板语言；「顶部一级 + 侧边二级 + 页头查询表单」（方向 D）只在确实有二级信息时才成立。纯 Bento / Aceternity 式装饰结构不适合这个面板。

## 2. 图表选型建议表

前提数据（台账 2026-10-18 口径 + 预览简报）：180 天窗口内约 55 天有请求、日请求中位数约 697、峰谷比 638 倍（见 `docs/RESEARCH-FINDINGS.md`）。也就是说，180 天日历热力里大部分格子是**缺失**而不是 0；这正是「未提供」规则最容易被破坏的地方，也决定了「失败构成」比「平滑趋势」更重要。

| 指标类型 | 推荐图型 | 备选 | 暗色注意点 |
| --- | --- | --- | --- |
| 请求量 / Token 用量（时间序列，1–3 系列） | 折线，1.5px 左右，不画点 | 面积图（填充透明度压到很低） | 只留水平网格；x 轴固定 3 个时间标签，y 轴 3 个；图例最多 3 项且纯文字；不要纯白线 |
| 成功率（0–100%） | 折线，y 轴固定 0–100 | 按天柱状 | 不要按值自动缩放；不要用红/绿大面积填充；低值靠线位与阈值线表达 |
| 延迟分位（p50 / p90 / p99） | 3 条折线 | 分位带（面积叠层） | 3 条线用 `--series-1/2/4`；线型（实/虚/点）辅助区分；不要同时画均值，避免第 4 条线 |
| 失败构成（互斥 6 类） | 横向条形列表（类别在 y 轴） | 单条 100% 堆叠条 | 前 3 类入图，「其他」进表；不用饼图/环图；不需要图例，因此天然满足「图例 ≤3」 |
| 失败原因 Top N | 横向条形 | 表格 + 行内微条 | 长原因截断加 tooltip；不要数据标签；按数量稳定排序 |
| 模型 / 节点排名 | 横向条形（Top 5） | 表格内微条 | 名称过长时截断，tooltip 给全名；无数据不补 0 |
| 配额消耗 / 剩余 | 进度条 / bullet | 水平堆叠条 | 轨道用 `--surface-2`，填充用 `--accent`；超限用 `--red`；不要仪表盘（占面积、难比较） |
| 缓存命中率 | KPI + sparkline | 单条折线 | sparkline 不显示轴与标签；缺失点断开，不连成 0 |
| 节点延迟分布 | 直方图（固定分箱） | 横向条形 | 分箱边界写在轴上；不要叠加密度曲线；柱间留 1px 底色缝 |
| 请求热力（180 天） | 日历热力（GitHub 式），缺失留空 | 7×24 周-小时热力（按小时桶） | **缺失 ≠ 0**；180 天里只有约 55 天有数据，绝大多数格是缺失；缺失格不参与 `visualMap`，低端色不能接近底色；色阶图例 3 档 |
| 请求节律（星期 × 小时） | 7×24 热力 | 日历热力 | 5 档色阶足够；色阶图例只给 3 个阈值；低端色要能看见 |
| 日志量 / 级别 | 堆叠柱（≤3 个级别） | 折线 | 固定堆叠顺序（error / warn / info）；图例不带计数；网格弱于柱 |

**暗色总则**

1. 不要直接吃 `echarts.init(dom, 'dark')` 的成品配色：它自带背景与调色板，会和现有 token 打架。更稳的是用 `registerTheme` 把现有 `--series-* / --text-sec / --border` 映射进去，并把 `backgroundColor` 设为 `transparent`，让卡片底色统一由 CSS 决定（主题机制见 [ECharts Style 文档](https://echarts.apache.org/handbook/en/concepts/style/)）。
2. 轴与网格分两级：轴线略强、网格线更弱；文字用 `--text-sec` / `--text-ter`，不要纯白。
3. 数据标签默认全关；只在 hover/tooltip 出现。ECharts 的 `label.show` 必须逐图确认，库示例经常默认开。
4. 图例默认不放数字；ECharts 的 formatter 不要写 `{c}`；超过 3 项就改成「表 + 条形列表」，不要挤图例。
5. 热力/面积的低端色必须离底色有可见差；缺失值与 0 用不同编码（缺失不入 series，单元格写「未提供」；0 才入 series）。
6. 轴刻度控制在 3 个：x 用 `interval` 指定显示哪些标签，y 用 `splitNumber` 并截图验收；默认值通常会多于 3 个。

**ECharts 示例适配（暗色）**

- **时间序列**：`line-stack` / `line-gradient` 的结构可直接用，但渐变填充要压到很低；暗色下高饱和面积会淹没细线。
- **分布**：`bar-stack` 改成「单条 100% 堆叠」或横向条形列表；`scatter-simple` 只在确实要看离群点时用，否则只会增加读图成本。
- **日历热力**：`calendar-heatmap` 的骨架可用，但 180 天窗口里只有约 55 天有数据，自动 `visualMap` 会让缺失格和 0 值都贴近底色，看起来像「全都为 0」。正确做法是缺失格不入 series（或单独渲染为空框），配「未提供」说明；不要为了画面完整去补 0。
- **不要用**：`pie-simple`（类别一多、图例带数值）、`gauge-simple`（占面积且难比较）。

## 3. 导航范式对比表

| 形态 | 首屏横向成本 | 4 页 + 页面级筛选的适配 | 筛选器落点 | 密度 | 窄屏 | 主要风险 | 代表 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 左侧固定侧栏（A） | 中：常驻占宽 | 高：4 项稳定，页头可长期放筛选 | 页面 header | 高 | 折叠成窄轨 | 1280 宽下内容区被压；容易做成「后台模板」 | Linear / shadcn dashboard-01 / Cloudflare |
| 顶部横向（B） | 低：不占侧边 | 高：4 项正好，切换直观 | 页面 header | 高（去掉卡片外壳后） | 横向滚动 | 4 页以上会挤；长页面滚动后页头筛选不可见（需 sticky） | Plausible / Stripe 顶部栏 |
| 窄图标轨 + 画布（C） | 低：只占一条轨 | 中：页数少时反而浪费；靠 tooltip 记忆 | 顶栏 / 页 header | 最高 | 可横向滚动 | 可发现性差；面板级筛选/图例容易越权 | Grafana / Datadog |
| 顶部一级 + 侧边二级（D） | 高：两级 chrome | 中：只有页面内部确实有二级分区时才值 | 页 header + 查询表单 | 中 | 复杂，需折叠 | 4 个扁平页配两级导航属于过度设计 | Ant Design Pro（`layout: 'mix'`） |

**对 4 个页面的判断**

- 4 个页面是「扁平」的，不需要两级导航。D 的顶部+侧边在没有二级信息时只会增加噪声；如果设置页里确实要分「连接 / 模型 / 缓存推理 / 外观」，用页内 tab 或左侧分区即可，不必升级成全局二级侧栏。
- A 与 B 都能满足「页面级筛选只在 header」。A 的 header 更稳定（侧栏不参与滚动），B 需要把页头做成 sticky，否则滚到表格时筛选器消失。
- C 的面板画布与「页面级筛选」天然冲突：Grafana 的每个 panel 都能带自己的时间范围，这是它的能力，也是我们要避免的模式。用 C 就必须**删掉面板级时间选择器**，只保留页头一处。

## 4. 四个方向

> 四个方向按「导航 + 栅格 + 图表语言 + 信息密度」区分，不是同一套换色。
> 字号/圆角/间距均为**建议基调**，落地时以现有 token 和双主题截图验收为准。

> 草图里的 `——` 只表示版面位置，不代表真实数据；真实页面在没有数据时必须显示「未提供」，禁止用示例数字顶替。

### 方向 A · 值班控制台（Ops Console）

**一句话定位**：像值班台一样，左侧永远知道自己在哪，右侧一屏内看完「现在有没有事、哪里有事、下一步点哪」。

- **导航**：左侧固定侧栏，4 个一级项（总览 / 请求日志 / 节点池 / 设置）+ 底部连接状态；窄屏折叠为图标轨（现有 `static/admin.html:123` 已是 204px，可沿用结构，不建议再加宽）。
- **栅格与密度**：12 栏；顶部 4 个 KPI 一行；主图全宽；第二行「失败构成 + Top 模型」各半；表格全宽。页面纵向节奏是「KPI → 主图 → 异常 → 明细」，不堆装饰卡。
- **图表语言**：折线/条形为主，最多 3 系列；无数据标签；失败构成用横向条形列表，不用环图；热力只作为补充，不占主位。
- **字号 / 圆角 / 间距基调（建议）**：正文 14px（不低于 13px），元信息不低于 12px；卡片圆角沿用 12px；卡片内边距 16–20px；模块间距 12–16px。目标是把现有 `--radius` 与 14px 正文保留下来，不追小字。
- **适合谁**：运维/值班同学，1440px 以上桌面，长时间盯盘，需要快速判断「节点池是否健康、配额是否要炸、日志里有没有新错误」。

### 方向 B · 报告页（Report / Editorial）

**一句话定位**：把面板当成一份每天打开看的报告，从上往下读，不需要「进某个模块」的感觉。

- **栅格与密度**：单列为主；只有「失败构成 / Top 模型」这种短内容并排；KPI 不做 4 张卡，而是一行文字指标 + 细分隔线。卡片外壳基本取消，用 section 标题 + 1px 分隔线组织。
- **图表语言**：一张主图（请求量）承担叙事，其他图都降为辅助；breakdown 用条形列表；不使用环图；表格直接铺在页面上，不再套卡片。

### 方向 C · 面板工作台（Panel Workbench）

**一句话定位**：屏幕就是一块画布，指标是面板，点进去有检查器；为排障而生，不为「浏览」而生。

### 方向 D · 企业后台（Enterprise Admin）

**一句话定位**：把 4 个页面当成 4 张业务单据列表，页头是查询表单，左侧是页内目录，强调「可查询、可分页、可导出」。

- **栅格与密度**：12 栏；页头是「标题 + 面包屑 + 查询表单」三段；内容区以表格为主，图表只做汇总条；表格支持列设置、分页、导出。

- **字号 / 圆角 / 间距基调（建议）**：正文 13–14px；圆角 8px；控件高度统一（按钮/输入/下拉同一高度）；表格行高 36px 以上，保证可点。整体更像「系统」，不是「看板」。

### 5.2 具体冲突来源（按源）

1. **shadcn/ui dashboard-01：筛选器在卡片里**
   `chart-area-interactive.tsx` 把时间范围 `ToggleGroup` / `Select` 放在 `CardHeader` 右侧（[注册表源文件](https://ui.shadcn.com/r/styles/new-york/dashboard-01.json)）。这与「页面级筛选器只能在页面 header」正面冲突。可以借它的「侧栏 + KPI + 图 + 表」节奏，但时间范围必须上移到页头。
2. **shadcn/ui dashboard-01：KPI 卡带脚注与数字 delta**
   `section-cards.tsx` 每张卡有 `CardFooter` 两行解释文案，右上角是 `+12.5%` / `-20%` 徽标。脚注长度远超「24 个汉字」，delta 数字也会诱导在每个卡上堆解释。若用 A 的节奏，KPI 只留「标签 + 数值 + 一行 ≤24 字的状态」，delta 最多一个方向箭头，不给数字。
3. **Tremor：默认强调 delta 与渐变**
   官网首页示例就以带数值的图例/百分比、渐变面积和环图为主；这与「无数据标签」「图例不带数字」「控件走令牌」都有张力。可借它的 tracker/bar list 形态，不借默认装饰。
4. **Aceternity：结构是 landing page，不是看板**
   它的 blocks 以 Hero、Bento、Backgrounds 为主（[blocks](https://ui.aceternity.com/blocks)）。装饰性背景、动效、超大标题与「空白 ≤10%」「内容密度高」直接冲突。最多借空态插画或一个很克制的顶部光效，不能作为 4 页骨架。
5. **Ant Design Pro：`layout: 'mix'` + 硬编码主色 + 查询表单位置**
   官方默认配置是 `layout: 'mix'`、`colorPrimary: '#1677ff'`（[源码](https://github.com/ant-design/ant-design-pro/blob/master/config/defaultSettings.ts)）。前者在 4 个扁平页上属于过度设计，后者违反「控件颜色走主题令牌」。另外 `ProTable` 的查询表单传统上在表格上方的内容区，必须整体上移到页面 header，才能满足硬性偏好。
6. **Grafana / Datadog：面板级筛选与图例**
   面板画布允许每个 panel 自带时间范围、legend、单位，这是排障能力，但与「页面级筛选只在 header」「图例 ≤3 且无数字」冲突。用 C 的话，必须删掉面板级时间选择器，图例只能在页头统一出现。
7. **ECharts 示例与默认值：标签、刻度、热力色**
   官方示例为了演示，经常开数据标签、多刻度、自动 `visualMap`。直接复制 option 会同时踩「无数据标签」「轴 ≤3」两条。暗色下尤其要注意：自动 `visualMap` 的 min/max 会让稀疏数据的大多数格子接近底色，看起来像「没有数据」。
8. **Plausible / Umami 的「0」语义**
   这类产品里的 0 通常是「确实没有发生」；我们的缺失是「采集缺口/窗口未覆盖」，语义不同。照搬它们的 0 值呈现，会把「未提供」洗成 0，正是用户最反感的假数据。
9. **现状代码已经踩过的坑（不是新方向的问题，是迁移债）**
   - 热力图把缺失日补 0：`byDay[ds] || 0`（`static/admin.html:1486`）。
   - 环形图默认显示百分比标签：`label:{show:true,formatter:'{b}\n{d}%'}`（`static/admin.html:1559`）。
   - x 轴用 `interval:'auto'`（`:1432`）、y 轴未限制刻度（`:1433`），默认刻度会多于 3 个。
   - 图表里仍写死暗/亮 hex（如 `:1519`、`:1522` 的 `#7b87a5` / `#1b2434`），没有全部走 `--text-ter` / `--surface`。
   - 趋势卡的页面级筛选被放在卡片头部（`:536`–`:544`），这是本次要修的核心结构问题。
   - 导航目前是 5 项（`:451`–`:455`），重构要收敛到 4 项（总览 / 请求日志 / 节点池 / 设置）；否则「4 页」只是文案上的 4 页。

### 5.3 哪些方向不能直接用

- **C 面板工作台**：与「页面级筛选只在 header」直接冲突（面板级时间范围是它的核心能力），字号、面板描述、图例则是高风险默认值；实现成本也最高。**只能借「行点击 → 右侧抽屉」这一件事**，不能借它的面板语言与默认小字。
- **D 企业后台**：与「筛选器只在 header」直接冲突（ProTable 默认），且 4 个扁平页配两级导航是过度设计。**只能借「页头查询表单 + 表格分页/列设置」**，并且查询表单必须待在页头，不能下放到内容区。
- **B 报告页**：结构本身不冲突，但「单列 + 主图」很容易制造大留白，撞「空白 ≤10%」。如果选 B，必须做到：去掉卡片外壳、KPI 不做四张大卡、主图高度受控、表格紧接主图。
- **A 值班控制台**：没有结构性冲突，是最稳的底座。真正的风险是「卡片堆」和「通用后台感」，靠「一页最多 1–2 个卡片容器」和「表格/分隔线承担主体」来控制。

### 5.4 组合建议（不改方向前提下的最小风险）

- **底座用 A**：复用现有侧栏、`--radius`、14px 正文，改造量最小。
- **排版借 B**：KPI 不做四张大卡，失败构成用条形列表，减少卡片外壳；但保留 A 的侧栏。
- **下钻借 C**：请求日志的单条用右侧抽屉看 JSON/上下文；节点表保留 A 的行内展开。两种下钻分页使用，避免同一页出现两套交互。
- **查询表单借 D**：只把「查询/重置/列设置」放进页面 header，不引入第二级侧栏。

这样得到的形态是「A 的骨架 + B 的排版 + C 的下钻 + D 的页头表单」，四者的默认值都不照抄，硬性偏好才守得住。
