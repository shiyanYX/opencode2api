面板大改 · 预览导航

5 个离线预览，按下面的顺序点开就行。全部是本地文件，双击即可打开，不需要启动任何服务。

这些是效果预览，不是正在运行的面板。它们是为了定风格和布局做的静态样张，尚未上线；你现在用的面板（:8000）没有任何变化。

按这个顺序看

  1. 先看这个 风格样例：概览页 + 节点池长什么样

    u2b/style-specimen.html

    这是什么：把我们真实的「概览」和「节点池」两页，按 freellm 的视觉风格重画了一遍。这是全套里最能代表最终效果的一张。

    点开看什么：颜色是不是很“灰”（整页几乎看不到彩色）、卡片有没有阴影（应该没有，只有一圈细描边）、大数字是不是等宽的、小标签是不是灰色大写。

    打开风格样例 →
  2. 第 2 步 大框架：左侧栏换成顶栏之后的骨架

    u2a/shell-blueprint.html

    这是什么：只看“大框架”的那张 —— 把现在的左边竖栏换成顶部横条导航之后，整个页面怎么分区、内容往哪放。

    点开看什么：顶栏够不够高、导航项排得开不开；内容列是不是居中、有没有被拉得太宽；页面顶部的“标题 + 一句说明 + 右侧按钮”和下面一叠卡片的堆叠节奏。

    打开框架蓝图 →
  3. 第 3 步 截图：首屏不滚动那一张（1440×900）

    u2b/specimen-desktop-1440x900-fold.png

    这是什么：上一条样例页在 1440×900 屏幕上“第一屏”的截图，正好一屏、不用滚动。专门用来看信息密度的。

    点开看什么：一屏塞下了多少信息、会不会太挤或太空；最要紧的数字是不是不用滚动就能看到。

    打开截图 →

这三张是更早的探索稿（方向 A / B / C），后来上面的 U2a、U2b 已经把方向定下来了。它们仅作对比参照，不要当成实施依据；看的时候只体会“三个方向各自的取舍”即可。

  1. 仅参照 方向 A：运维监控台

    u2/direction-a-console.html

    点开看什么：信息密度上限长什么样 —— 一屏能铺多少指标；顺便感受一下“信息太多以后，还找得到重点吗”。

我们还差什么

  • 工作量比看上去小：「照 freellm 大改框架的真实工作量 ≈ +43 行（占 2,307 行的 +1.9%），零新增依赖、零构建、零 Go/Docker/测试改动；主要动作只有一个：把左侧栏换成顶栏。」
    出处：docs/research/U2a-freellm-shell-and-stack.md §0（结论速览）
  • “像不像”只差三件事：「照搬三件事就已经八成相似：① 卡片 24px 圆角 + 1px 细描边 + 零阴影；② 数值一律 20px 半粗等宽数字、标签一律 11px 大写灰色；③ 页面是“顶部横条导航 + 72rem 居中列 + 一叠等宽卡片”。」
    出处：docs/research/U2b-freellm-style-recipe.md §0（三句话总结）
  • 三处已知差异（都是我们主动选择的，不改也能看）：我们的导航是 204px 左侧栏（freellm 是顶部横条）；我们的卡片带阴影、数值 30px（freellm 是 0 阴影、20px）；我们的表格单元格内边距 10/12px（freellm 是 8px）。
    同上 U2b §0 第 2 条
