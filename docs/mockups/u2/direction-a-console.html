方向 A · 运维监控台

高信息密度、一屏看清全局、出问题一眼定位。目标用户是技术型运维——不怕密，就怕看不全。 本页是 U2 三方向初稿中的 A，仅用于选型，不是最终实现稿。

信息架构（用户第一眼看什么 → 怎么下钻）

  1. 第一眼 = 告警横幅 + 指标条。横幅只回答一个问题：是不是「整层不可用」；指标条第 4、5 格故意并排放置「池内可用 115/227」与「节点出口 0.0%（37 次）」——两个数打架就是事故本身。
  2. 第二眼 = 失败构成 + 出口维度拆解。左侧回答「坏成什么样」（闸门/连接/429/403/5xx），右侧回答「坏在哪」（订阅A 18.1% vs Webshare 99.1%）。两者都可点，点了直接落到具体调用记录。
  3. 主视图 = 节点健康矩阵（227 格热力格）。按源分组、颜色=状态、同档一色；悬浮/聚焦出「延迟 / 最近错误 / 冷却 / 评分」，点击在右侧钉住明细。要的是「一眼看出 订阅A 那一片全红」。
  4. 下钻 1 = 节点列表：评分列（轴条+数字）、分档徽章、可排序表头、行内展开「评分构成 + 理由枚举 + 最近失败时间轴 + 冷却来源」。
  5. 下钻 2 = 请求与故障：60 分钟堆叠时间轴 → 点格子筛时段；失败构成点类别筛类型；每条记录展开成出口跃迁链（failover ladder）+ 事件时间轴 + req_id/final_status/dial_ms。

U1 §8 数据契约的落点（硬要求逐条）

要求本原型落点
评分列节点表「评分」：轴条 + 0–100 数字；成分明细在行内展开区（components[] 数组长度自适应，不做固定三轴）
分档徽章「分档」列：优秀 ≥80 一般 60–79 较差 <60 无数据；同档一色，不按数值连续插值
排序入口表头三态循环 + localStorage 持久化；默认评分降序；空值两个方向都排最后（lib/table-sort.ts 的语义）
行内下钻行展开：样本量 / 各成分值 / 理由枚举（recent_errors · cooldown · penalty）/ 该节点最近失败时间轴 / 冷却来源
value 为空或 samples=0 ⇒ 「无数据」虚线空条 + 无数据；单独成组置末（表里有一行分组头：「以下 N 个节点无评分样本（未参与排序）」），有任何数据时才可能显示 0 分
成功率带样本量96.4% (312) / 0.0% (86)；样本为 0 时整格 无数据（wall 上不会出现「0.0%」和「不知道」混淆）

刻意放弃 / 妥协了什么

  • 放弃了「池子健康」这个大数字。现存面板首屏是 4 张状态卡；本方向把它降级成指标条第 4 格，让位给「节点出口成功率」。代价：不熟悉这套系统的人第一眼会觉得「可用节点」不够醒目——这是有意的，因为那个数字曾经骗过我们 8 小时。
  • 放弃了移动端卡片化堆叠。390px 下只做「裁列 + 横向滚动」，且明确列出被裁的列（协议/指纹）。理由：227 行 × 9 列在手机上堆成卡片后，一屏只能看 2 个节点，「看不全」这个核心目标直接失效。
  • 放弃了长表格。矩阵给「定位」，列表给「排序与下钻」，两者都必须有——矩阵不能排序，列表不能一眼扫全，这是本方向唯一的重复信息区。
  • 放弃了页面转场动画与卡片阴影（现存面板两者都有）。代价：切换页面略显生硬；收益：密排卡片之间不再互相「浮起来」，边界靠 border 说话，长时间盯盘眼睛更省。
  • 放弃了独立「节点健康大图」视图（雷达/散点）。依据 U1 §8.3：评分是排序工具不是分析工具，运维的动作是「下一个该切谁」，不是欣赏分布。
  • 未实现：真实写操作（切节点 / 测速 / 保存配置）只有 toast 示意；命令面板（U1 §7.10 判定收益低）；拖拽排序（同上）。
  • 口径妥协：节点表的请求数/成功率来自浏览器端折叠的 24h 调用记录；如果后端将来给 /api/nodes 加服务端聚合，UI 不需要改（每格都标注了 n 与窗口）。
  • 阈值妥协：评分三档 <60 / 60–79 / ≥80 沿用 U1 §11 #9 的建议值，不是既定设计。

从 U1 报告里具体用了哪些结论

  • §2.2 字号层级：正文 12/14px、标签 11px、统计值 20px（现存面板是 30px/26px，粗一档）
  • §2.2 / §5.2 body 级 tabular-nums（不再逐处 .num，会漏）
  • §2.1 中性色走灰阶、彩度让给状态语义（现存面板把 --accent 同时当主按钮/当前节点/图表系列）
  • §2.4 靠 border + surface 分层、不用阴影（只给浮层阴影）
  • §3.4 / §8.2 ⑤ AxisNoData 的诚实占位：无样本 → 虚线空条 + 「无数据」，且不参与排序、单独成组置末
  • §4.2 排序三态 + localStorage + 空值双向最后；并显式标注「排序只覆盖已加载的 N 行」
  • §4.4 字段缺失显示占位而不是 0；§8.4 契约（value/samples/components/reasons，components 是数组）
  • §4.1 / §7.7 分层新鲜度（节点 10s / 闸门 5s / 统计 30s），后台标签页不停止刷新
  • §6 第 1 件：把「调用日志 → 节点分析」的聚合搬进节点页（本原型用同一个 aggregateByExitNode() 供两处调用）
  • §7.1 明确不为了 CSP 改事件模型：本原型继续用内联 onclick（与现存面板 75 处一致），事件委托是独立的一件事
  • §7.6 tooltip 不能只有 hover：矩阵格子支持 悬浮 + 键盘聚焦 + 点击钉住
  • §3.3 带动作的空态（「一个没有下一步的空态是死路」）
